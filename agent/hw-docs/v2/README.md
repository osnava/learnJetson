# hw-docs v2 — docling substrate, RAG layer (issue #28)

Decision record for the corpus rebuild. The #27 spike (see
[`../explore/FINDINGS.md`](../explore/FINDINGS.md)) chose **JSON as the
source of truth, md as the rendering agents read**; this directory is
that substrate, wired into `fetch.sh`. v1's pymupdf machinery is retired
with intent recorded below — nothing was adapted in place, per the issue's
hard wall.

## Files

| File | Role |
|---|---|
| `build.py` | the pipeline `fetch.sh` calls: docling convert → JSON (core docs) + normalized md → HybridChunker chunks with heading/page provenance → MiniLM embeddings → per-doc index shards in `md/index/` |
| `normalize.py` | **the** normalization spec (escapes, whitespace, wrapped-token reconstruction) — shared by the renderer here, `search.py`, and `grade.py`. Its docstring is the rulebook. |
| `search.py` | provenance-carrying semantic search over `md/index/` — the step between INDEX routing and declaring a question not-sourceable |
| `grade.py` | the structural citation grader (issue #29): `doc §section (p. N)` + quote resolved against the JSON's heading objects and per-object `prov.page_no` — section spans, page membership and quote occurrence are all structural, no text-stream anchors or span heuristics |
| `test_*.py` | synthetic tiers (run anywhere; `test_build.py`'s chunker tier needs docling_core and the spike JSON — loud SKIP elsewhere) |
| `fixtures/demo-doc.json` | committed docling JSON for `test_grade.py`'s synthetic tier — furniture-only pages, unnumbered headings, wrapped and dehyphenated cells, the §name form |

## What lands where (all gitignored, regenerated by `fetch.sh`)

```
md/<doc>.md            normalized rendering agents read + grep
md/<doc>.json          docling source of truth, per-object prov.page_no
                       (five core docs only — a TRM JSON would be ~970 MB)
md/<doc>.*.csv         pinmux sheets (xlsx path unchanged from v1)
md/index/*.chunks.jsonl  chunk records: {doc, headings, pages, text}
md/index/*.emb.npy       MiniLM embeddings, L2-normalized float32
md/index/*.meta.json     shard bookkeeping (model, dim, page span)
md/index/wrap_table.json corpus-confirmed wrapped-token joins
```

## Retrieval flow (mirrored in ../AGENTS.md)

1. **Route** the question through [`../INDEX.md`](../INDEX.md) → read/grep
   that section.
2. Routing misses? **Search**: `python v2/search.py "question"` — hits
   carry `doc §heading (p. N)` with the page resolved from docling object
   provenance. Exit 2 = no index (corpus not fetched — not the agent's
   fault).
3. Neither? **Declare not-sourceable** with a redirect — never guess.

## Normalization (one place: `normalize.py`)

- `\_` → `_` — the only escape docling emits in this corpus.
- whitespace collapses for matching (`canonical`), md rendering keeps
  docling's line/table layout (`render`).
- wrapped identifiers: locally unambiguous pieces join always
  (`FORCE_ RECOVERY`); ambiguous pairs join only when the corpus confirms
  the joined form occurs standalone (`GP70_UART1_TXD_BOOT2_STRAP` does;
  two real pin names `I2C2_SDA I2C2_SCL` never do). The confirmed pairs
  live in `wrap_table.json`; search applies the table at load time, so
  retrieval stays current even if an md rendering predates a table entry.

## TRM grind (operator runbook)

`fetch.sh --full` starts the TRM conversion **detached** (~7.3 h measured
extrapolation on GPU; md-only, no JSON):

```
tail -f agent/hw-docs/md/index/orin-trm.build.log
```

It converts in 250-page slabs; each slab's shard is written atomically
and skipped on rerun, so an interrupted grind resumes where it stopped —
just run `fetch.sh --full` again. Slab chunks derive their heading
breadcrumb from within the slab: a section spanning a slab boundary may
show a partial breadcrumb; page provenance is always exact.

## Decisions worth remembering

- **Schematics go through docling too** (md + chunks, no JSON): one
  conversion substrate; the concept-schematics PDF is born-digital vector
  art, so net names and refdes come out as greppable text items with page
  provenance.
- **Chunks serialize as markdown** (`MarkdownDocSerializer` provider) —
  table rows stay rows, so retrieved snippets stay greppable; the default
  key-value linearization does not.
- **Embeddings**: a small local model
  (`sentence-transformers/all-MiniLM-L6-v2`, 23M params, 384-dim),
  mean-pooled, GPU when present — also the chunker's tokenizer, so chunk
  size and model window agree (256 tokens).
- **Stale-md caveat**: a single-document rebuild re-renders only that
  document's md; wrap-table entries discovered later apply to search
  immediately (load-time) but not retroactively to older md files. A full
  `fetch.sh` run after deleting `md/*.md` re-renders everything.

## Retirement of the pymupdf machinery (intent, per issue #28)

| v1 | Superseded by | Deleted when |
|---|---|---|
| `convert.py` PDF engine + `<!-- p.N -->` anchors | `v2/build.py`, JSON provenance | #30 |
| `convert.py` figure cull | `--image-export-mode placeholder` equivalent (spike: zero image links, JSON keeps picture provenance) | #30 |
| `convert.py` pdftotext fallback | docling is the only path; absence is a hard error with install guidance | #30 |
| `convert.py` xlsx→csv | inherited **verbatim** into `v2/build.py` (explicitly outside the hard wall) | with convert.py |
| `grade.py` span/anchor heuristics | `v2/grade.py` structural grader — heading objects + `prov.page_no`, quotes via the shared normalization; v1's answer-surface parser lives on inside it | **#29 green** — v1 file unused, deletes with #30's sweep |
| `check.py` anchor/heading-floor lint | #30 provenance-based linter (JSON pages == PDF pages) | #30 green |

v1 files stay in place, unused by `fetch.sh`, until their replacements
are green — the corpus itself is already produced by v2 only.

## CI

Docling (multi-GB models, GPU-friendly) is too heavy for per-push
conversion: the corpus and its checks are **operator-side**, as they
already were for the login-gated datasheet. CI runs the synthetic test
tiers (fixtures carry the contract) plus the corpus-independent linter
sections. The full CI story is #30's scope.
